# Browser tests (Playwright)

Full-stack tests: a real browser against the Docker stack (Next.js, Express API, Postgres).
Only Claude is replaced, by the API's `LLM_PROVIDER=fake`, so no API key is needed.

## Run locally

Needs Docker, Node 24 and the API repo checked out next to this one (`../ai-cv-builder-api`,
or set `API_DIR`). Ports 3000 and 4000 must be free.

```bash
npm ci
npx playwright install chromium
./e2e/stack.sh up      # builds and starts the stack, waits until it is healthy
npm run test:e2e
./e2e/stack.sh down    # stops it and deletes its database
```

`stack.sh up` copies both repos to a scratch folder (`$E2E_STACK_DIR`, default
`$TMPDIR/cvb-e2e-stack`) without their `.env` files, writes a fresh `.env` from the API's
`.env.example` with `LLM_PROVIDER=fake`, and runs `docker compose -p cvb-e2e up --build --wait`
there. Your own `.env` (and API key) is never read. Run it again after changing either repo.

- `npx playwright test --project=mobile-chromium` runs only the phone tests;
  `npx playwright show-report` opens the HTML report of the last run.
- Against another deployment: `E2E_BASE_URL=https://cv.example.test npm run test:e2e`. It must
  run the fake LLM, or the tests spend real Claude calls and their drafts differ.
- Sign-ups and logins share one rate-limit bucket (100 per 15 minutes) behind the Next.js
  rewrite, which is about three full runs. `docker compose -p cvb-e2e restart api` resets it.

## What is covered

| Spec                 | Scenario                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `auth.spec.ts`       | sign up, log out, `?next=` redirect and back after login, wrong password, taken email      |
| `generation.spec.ts` | pasted text with a reload mid-generation; PDF upload with a Cyrillic name                  |
| `editing.spec.ts`    | autosave of summary and bullets, adding and removing a bullet, reload and a second tab     |
| `questions.spec.ts`  | answer while the editor is read-only, the answer lands in Education, skip a question       |
| `review.spec.ts`     | a flagged summary is dismissed, the removed skill is listed                                |
| `pdf-export.spec.ts` | the download is a PDF whose text layer contains the name                                   |
| `isolation.spec.ts`  | another user's CV is "not found" in the UI and 404 in the API; the list shows only own CVs |
| `cv-list.spec.ts`    | delete from the list, with cancel and confirm                                              |
| `mobile.spec.ts`     | Pixel 7: Edit / Preview / Questions tabs, bottom action bar, no horizontal scrolling       |

`desktop-chromium` runs every spec except `mobile.spec.ts`, which only `mobile-chromium` runs.
Every test signs up its own user, so tests run in parallel and in any order.

Determinism comes from the fake LLM: it copies the source text, and for a technology in the
target role that the source lacks (React in "Senior React Developer") it adds that keyword to
the summary and skills, which the verifier flags and removes. `FAKE_LLM_DELAY_MS=1500` keeps a
generation running long enough to reload the page in the middle of it; with 400 ms a slow
runner would reload after the CV was already done.

`fixtures/ivan-petrov-cv.pdf` is generated by `node e2e/fixtures/make-cv-pdf.mts` (Chromium
prints the HTML, so the PDF has a real text layer).
